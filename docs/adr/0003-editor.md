# ADR 0003 · Редактор

Статус: **предложено**, требует проверки · 26.09.2026

## Контекст

ТЗ, раздел 2: «Markdown-редактор с экранированным/санитизированным preview. В первой версии допускается plain-text source + preview. Выбор редакторской библиотеки — ADR с проверкой IME и мобильной клавиатуры». Документ — блоки со стабильными UUID; редактор не должен пересоздавать блоки на каждое нажатие.

## Предлагаемое решение для v1

- Редактор блоков без сторонней библиотеки: markdown-блок — автоматически растущий `<textarea>`, task-блок — чекбокс и однострочное поле, attachment-блок — карточка `AttachmentCard`. Каждый элемент привязан к `id` блока, поэтому id сохраняются естественно.
- Enter в конце задачи создаёт новую задачу; Backspace в пустом блоке удаляет его и переводит фокус на предыдущий. Разбиение и склейка создают новые id только для новых блоков.
- Preview Markdown строится из текста без raw HTML, с санитизацией; ссылки открываются с `rel="noopener noreferrer"`. Библиотека рендеринга выбирается отдельно после проверки её поведения на XSS-наборе.
- Нажатия объединяются до 150 мс перед `editNote()`; blur, навигация и уход в фон сохраняют сразу.

Нативные `textarea`/`input` выбраны потому, что с ними IME и мобильные клавиатуры работают на стороне платформы. Это предположение, а не результат проверки.

## Что нужно проверить до статуса «принято»

- IME: русская раскладка, японский и китайский ввод (composition events), автозамена и подсказки на Android (Gboard) и iOS.
- Экранная клавиатура: курсор не закрывается нижней навигацией, safe areas, прокрутка к курсору.
- Вставка текста с несколькими абзацами и задачами (`- [ ]`) — разбиение на блоки.
- Отмена (Ctrl/Cmd+Z) в пределах блока и между блоками.
- Диктовка: вставка в позицию курсора текущего блока.
- Экранные дикторы: NVDA, VoiceOver, TalkBack.
